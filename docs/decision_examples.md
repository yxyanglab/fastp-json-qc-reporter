# Claude Code 决策回答示例

这个项目的核心不是单纯生成表格，而是把 fastp 质控结果转换成“能不能继续分析”的判断。脚本负责提取和汇总指标，Claude Code skill 负责把结构化结果解释成自然语言决策。

## 场景 1：所有样本合格

用户输入：

```text
/fastp-check 分析 /Users/yeye/Desktop/fastp_demo 里的数据
```

脚本输出摘要：

```text
✓ 所有 12 个样本质控合格，可以正常使用。
```

Claude Code skill 应回答：

```text
全部合格。12 个样本所有指标均在阈值范围内，可以进入后续分析。

- 过滤率 0.01%-0.02%，数据损耗很小
- % > Q30 为 94.92%-98.03%，整体测序质量很好
- GC content 为 41.4%-50.7%，均在 35%-65% 阈值范围内
- |A-T| 和 |C-G| 均小于 10%，碱基组成没有明显异常

B-5 到 B-8 的 GC content 约为 42%，低于其他样本但仍在合格范围内。可以继续后续分析，报告中可简单备注这一批样本 GC 偏低但未超过异常阈值。
```

## 场景 2：存在异常样本

脚本输出摘要：

```text
QC verdict: 1/2 samples need attention.
problem_sample    FAIL    Filter 24.00%    Q30 73.50%    GC 70.20%    |A-T| 16.12%
```

Claude Code skill 应回答：

```text
有 1/2 个样本质控异常，暂不建议所有样本直接进入后续分析。

problem_sample 存在以下问题：
- 过滤率 24.00%，高于 15% 阈值，提示低质量 reads 或接头污染较多
- Q30 为 73.50%，低于 80% 阈值，提示过滤后整体测序质量偏低
- GC content 为 70.20%，高于 65% 阈值，需结合物种背景排查污染或建库偏差
- |A-T| 为 16.12%，高于 10% 阈值，需检查 read composition、链特异性设置或随机引物偏好

建议先复查 problem_sample 的 fastp HTML/MultiQC 图。如果低质量区域集中在 reads 前端或尾端，可以重新运行 fastp 并增加 `--cut_front`、`--cut_tail` 或调整质量阈值；如果 GC 和碱基组成异常仍存在，应进一步检查样本污染、建库批次或样本混淆。good_sample 可以继续后续分析。
```

## 展示重点

GitHub 中的表格展示“工具能提取什么指标”，决策回答展示“工具怎样帮助分析人员做判断”。这两部分一起体现项目价值：

- 减少逐个打开 fastp HTML 的人工检查
- 补足 MultiQC 偏展示、缺少直接判读结论的问题
- 把人工质控经验整理成可复用规则
- 用 Claude Code 将规则解释为面向后续分析的建议
